# General mechanism

The acceptance filter compares each received frame against a Code set by the `M` command and a Mask set by the `m` command. The filter mode is selected by the `W` command, and the 4-byte Code and Mask are interpreted differently depending on the selected mode.


# Dual filter mode (W0)

This mode is not yet implemented.
The filter always passes all frames in this mode for now.


# Single filter mode (W1)

This mode is not supported by this firmware.


# Simple filter mode (W2)

### Mechanism

The received frames are filtered based solely on their identifier extension bit (IDE) and CAN ID. The IDE value is inverted (`~IDE`), combined with the CAN ID, and compared against the corresponding bits of the Code and Mask. This inversion is intended to make the Code value visually readable: extended CAN IDs appear directly in the 4-byte value, while base CAN IDs are tagged by a leading `1` in the MSB.

A received frame is accepted if the following condition is satisfied for every bit:

` (Code) & (~Mask) == (Rx frame) & (~Mask) `

A `1` bit in the Mask makes the corresponding bit don't-care, so the comparison effectively applies only to bits where the Mask is `0`.

The bit mappings are shown below, where the top row indicates the bit position within an 8-bit byte (`AC0`-`AC3` or `AM0`-`AM3`), the body shows the mapped CAN ID bit position, `~` denotes the `~IDE` bit, and `.` denotes an unused (don't-care) bit.

Mapping for a base CAN ID (11 bits, `~IDE` = `1`):

```
bit (in reg) :   7   6   5   4   3   2   1   0
AC0 / AM0    :   ~   .   .   .   .   .   .   .
AC1 / AM1    :   .   .   .   .   .   .   .   .
AC2 / AM2    :   .   .   .   .   .  10   9   8
AC3 / AM3    :   7   6   5   4   3   2   1   0
```

Mapping for an extended CAN ID (29 bits, `~IDE` = `0`):

```
bit (in reg) :   7   6   5   4   3   2   1   0
AC0 / AM0    :   ~   .   .  28  27  26  25  24
AC1 / AM1    :  23  22  21  20  19  18  17  16
AC2 / AM2    :  15  14  13  12  11  10   9   8
AC3 / AM3    :   7   6   5   4   3   2   1   0
```

### Examples

Example 1:
* Mode: `W2[CR]`
* Code: `M00000000[CR]`
* Mask: `mFFFFFFFF[CR]`

All bits are disabled by acceptance mask i.e. all frames are received.
This is default when power on.


Example 2:
* Mode: `W2[CR]`
* Code: `M80000100[CR]`
* Mask: `m00000000[CR]`

The base CAN ID `0x100` is accepted and the other base CAN IDs are ignored.
All extended CAN IDs are ignored.


Example 3:
* Mode: `W2[CR]`
* Code: `M18DB0000[CR]`
* Mask: `m0000FFFF[CR]`

All extended CAN IDs between `0x18DB0000` and `0x18DBFFFF` are accepted.
The other extended CAN IDs and all base CAN IDs are ignored.


Example 4:
* Mode: `W2[CR]`
* Code: `M00000100[CR]`
* Mask: `m80000000[CR]`

The base CAN ID `0x100` and the extended CAN ID `0x00000100` are accepted and the other CAN IDs are ignored.
Setting bit 7 of `AM0` to `1` (i.e. the leading `8` in `m80000000`) marks the `~IDE` bit as don't-care, so the same low CAN ID matches both base and extended frames.
