# General mechanism

The acceptance filter compares each received frame against a Code set by the `M` command and a Mask set by the `m` command. The filter mode is selected by the `W` command, and the 4-byte Code and Mask are interpreted differently depending on the selected mode.


# Dual filter mode (W0)

### Mechanism

In dual filter mode, the 4-byte Code and Mask are split into two independent filters (`Filter 1` and `Filter 2`), each compared against the CAN ID of the received frame. A frame is accepted if **either** filter matches; the two filters work as a logical OR. This allows accepting two disjoint groups of CAN IDs that a single filter could not express.

Only the CAN ID is used for the acceptance decision. The bit positions corresponding to the `RTR` bit and the first data byte (`DB1`) in the original SJA1000 dual filter layout are accepted as input but are not compared. This is a simplification of LAWICEL / SJA1000 behavior; for filtering by CAN ID (the common case) the behavior is identical.

A frame is accepted by a filter if the following condition is satisfied for every used bit:

` (Code) & (~Mask) == (Rx frame) & (~Mask) `

A `1` bit in the Mask makes the corresponding bit don't-care, so the comparison effectively applies only to bits where the Mask is `0`.

The same 4-byte Code and Mask apply to both base and extended frames; the bit mapping is selected by the frame's `IDE` bit at the time of reception. A configuration intended for one frame type may incidentally match the other type if its bit pattern happens to coincide.

In the diagrams below, the top row indicates the bit position within an 8-bit byte (`AC0`-`AC3` or `AM0`-`AM3`), the body shows the mapped CAN ID bit position, and `.` denotes a bit position that is accepted as input but not used for filtering.

Mapping for a base CAN ID (11 bits):

```
bit (in reg) :   7   6   5   4   3   2   1   0
AC0 / AM0    :  10   9   8   7   6   5   4   3    Filter 1
AC1 / AM1    :   2   1   0   .   .   .   .   .
AC2 / AM2    :  10   9   8   7   6   5   4   3    Filter 2
AC3 / AM3    :   2   1   0   .   .   .   .   .
```

Mapping for an extended CAN ID (29 bits):

```
bit (in reg) :   7   6   5   4   3   2   1   0
AC0 / AM0    :  28  27  26  25  24  23  22  21    Filter 1
AC1 / AM1    :  20  19  18  17  16  15  14  13
AC2 / AM2    :  28  27  26  25  24  23  22  21    Filter 2
AC3 / AM3    :  20  19  18  17  16  15  14  13
```

For extended CAN IDs, only the upper 16 bits (`ID.28-ID.13`) of the 29-bit identifier are filtered; the lower 13 bits and the `RTR` bit are not used.

### Examples

Example 1:
* Mode: `W0[CR]`
* Code: `M00000000[CR]`
* Mask: `mFFFFFFFF[CR]`

All bits are disabled by acceptance mask i.e. all frames are received.


Example 2:
* Mode: `W0[CR]`
* Code: `MC03FC03F[CR]`
* Mask: `m001F001F[CR]`

The base CAN ID `0x601` is accepted (both filters are set to the same ID); other base CAN IDs are ignored.
Note: the same Code and Mask, when interpreted under the extended layout, also incidentally accept extended CAN IDs in the range `0x18040000` - `0x1807FFFF`.


Example 3:
* Mode: `W0[CR]`
* Code: `M20004000[CR]`
* Mask: `m001F001F[CR]`

The base CAN IDs `0x100` (matched by Filter 1) and `0x200` (matched by Filter 2) are accepted; other base CAN IDs are ignored.
This is the typical use case of dual filter mode: accepting two disjoint identifiers that a single filter cannot express.
Note: the same Code and Mask, when interpreted under the extended layout, also incidentally accept extended CAN IDs in the ranges `0x04000000` - `0x0403FFFF` (Filter 1) and `0x08000000` - `0x0803FFFF` (Filter 2).


Example 4:
* Mode: `W0[CR]`
* Code: `MC6D7C6D7[CR]`
* Mask: `m00070007[CR]`

All extended CAN IDs in the range `0x18DA0000` - `0x18DAFFFF` are accepted (both filters are set to the same range).
Note: the same Code and Mask, when interpreted under the base layout, also incidentally accept base CAN ID `0x636`.


# Single filter mode (W1)

This mode is not supported by this firmware.


# Simple filter mode (W2)

### Mechanism

The received frames are filtered based solely on their identifier extension bit (IDE) and CAN ID. The IDE value is inverted (`~IDE`), combined with the CAN ID, and compared against the corresponding bits of the Code and Mask. This inversion is intended to make the Code value visually readable: extended CAN IDs appear directly in the 4-byte value, while base CAN IDs are tagged by a leading `1` in the MSB.

A received frame is accepted if the following condition is satisfied for every bit:

` (Code) & (~Mask) == (Rx frame) & (~Mask) `

A `1` bit in the Mask makes the corresponding bit don't-care, so the comparison effectively applies only to bits where the Mask is `0`.

The bit mappings are shown below, where the top row indicates the bit position within an 8-bit byte (`AC0`-`AC3` or `AM0`-`AM3`), the body shows the mapped CAN ID bit position, `~` denotes the `~IDE` bit, and `.` denotes an unused (don't-care) bit.

Mapping for a base CAN ID (11 bits, `~IDE` = `1`):

```
bit (in reg) :   7   6   5   4   3   2   1   0
AC0 / AM0    :   ~   .   .   .   .   .   .   .
AC1 / AM1    :   .   .   .   .   .   .   .   .
AC2 / AM2    :   .   .   .   .   .  10   9   8
AC3 / AM3    :   7   6   5   4   3   2   1   0
```

Mapping for an extended CAN ID (29 bits, `~IDE` = `0`):

```
bit (in reg) :   7   6   5   4   3   2   1   0
AC0 / AM0    :   ~   .   .  28  27  26  25  24
AC1 / AM1    :  23  22  21  20  19  18  17  16
AC2 / AM2    :  15  14  13  12  11  10   9   8
AC3 / AM3    :   7   6   5   4   3   2   1   0
```

### Examples

Example 1:
* Mode: `W2[CR]`
* Code: `M00000000[CR]`
* Mask: `mFFFFFFFF[CR]`

All bits are disabled by acceptance mask i.e. all frames are received.
This is default when power on.


Example 2:
* Mode: `W2[CR]`
* Code: `M80000100[CR]`
* Mask: `m00000000[CR]`

The base CAN ID `0x100` is accepted and the other base CAN IDs are ignored.
All extended CAN IDs are ignored.


Example 3:
* Mode: `W2[CR]`
* Code: `M18DB0000[CR]`
* Mask: `m0000FFFF[CR]`

All extended CAN IDs between `0x18DB0000` and `0x18DBFFFF` are accepted.
The other extended CAN IDs and all base CAN IDs are ignored.


Example 4:
* Mode: `W2[CR]`
* Code: `M00000100[CR]`
* Mask: `m80000000[CR]`

The base CAN ID `0x100` and the extended CAN ID `0x00000100` are accepted and the other CAN IDs are ignored.
Setting bit 7 of `AM0` to `1` (i.e. the leading `8` in `m80000000`) marks the `~IDE` bit as don't-care, so the same low CAN ID matches both base and extended frames.
